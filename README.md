# Глава 2: лаборатория индексации LangChain

Демонстрационный проект для студентов по книге Майо Ошина и Нуну Кампоса «Изучаем LangChain», глава 2, печатные страницы 49–82. Сценарий: подготовить индекс вымышленной базы знаний учебного центра «Орбита» и найти фрагменты о стипендиях, библиотеке и экзаменах.

**Цель:** увидеть весь путь `файл → Document → чанк → эмбеддинг → векторное хранилище`, затем изменить данные и проверить обновление индекса. Генерация ответа по найденному контексту относится к главе 3 и в основной практикум не входит.

## Быстрый старт без ключа

Нужны Python 3.12–3.13 (рекомендуется 3.12) и интернет для установки зависимостей. Выполняйте команды из корня распакованного проекта.

```bash
python -m venv .venv
# Linux / macOS
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements-lock.txt
python -m pip install -e ".[dev,notebook]"
chapter2 inspect
chapter2 index --demo
chapter2 search "Как получить стипендию?" --demo
chapter2 multivector "Библиотека" --demo
```

`--demo` работает без ключа и без сетевых запросов к моделям: слова хешируются в вектор из 256 чисел. Это иллюстрация механики индекса, **не семантический поиск**. Результаты поиска по синонимам не демонстрируют качество LLM-эмбеддингов. Все учебные сведения в `data/` вымышлены.

## Подключение api.vsellm.ru

```bash
cp .env.example .env
# Windows PowerShell: Copy-Item .env.example .env
```

Заполните локальный `.env`:

```dotenv
OPENAI_BASE_URL=https://api.vsellm.ru/v1
OPENAI_API_KEY=ваш_ключ
EMBEDDING_MODEL=точный_ID_доступной_модели_эмбеддингов
CHAT_MODEL=точный_ID_доступной_чат_модели
CHUNK_SIZE=500
CHUNK_OVERLAP=100
```

```bash
chapter2 models
chapter2 index
chapter2 search "Какая финансовая помощь доступна студентам?"
chapter2 multivector "Как продлить книгу?"
```

`models` обращается к стандартному `GET /v1/models`. Он может быть недоступен у провайдера; тогда возьмите ID моделей из кабинета. Список ID сам по себе не гарантирует поддержку эмбеддингов. Для основной индексации требуется **`POST /v1/embeddings`**: доступ к чат-моделям не означает доступ к embedding-моделям. `CHAT_MODEL` нужен только для дополнительного `multivector`, использующего `/chat/completions`.

`OpenAIEmbeddings` получает `base_url` явно. Включены `check_embedding_ctx_length=False` и `encoding_format="float"`: стороннему провайдеру отправляются строки, а ожидаются числовые векторы. Длинные тексты заранее делятся на чанки. Размер чанка измеряется в символах, лимит модели обычно — в токенах; при необходимости уменьшите размер. Параметр `dimensions` не навязывается провайдеру.

В этой сборке реальный доступ к vsellm не проверялся: ключ и ID моделей не предоставлены. Проверен формат HTTP-запроса через подменный транспорт настоящего SDK. Если провайдер не поддерживает embeddings, понадобится отдельная embedding-модель/служба; одной чат-моделью этот endpoint заменить нельзя.

Индексация и поиск в реальном режиме расходуют средства на эмбеддинги; `multivector` дополнительно вызывает чат-модель для каждого исходного документа/страницы и строит временный индекс заново. Документы и поисковые запросы передаются выбранному провайдеру. В проект не включён текст учебника: используются небольшие авторские примеры, включая готовый одностраничный `data/cafeteria.pdf` на английском для проверки PDF-загрузчика.

## Как проводить демонстрацию

1. `chapter2 inspect` — покажите `page_content`, `source`, `page` (для PDF), `start_index` и границы чанков.
2. `chapter2 index --demo` — первый запуск сообщает `num_added`, второй — `num_skipped`. Вторая индексация не вычисляет эмбеддинги неизменённых чанков.
3. `chapter2 search "Библиотека" --demo` — найдите исходные фрагменты; меньшее `cosine distance` означает большую близость. Это расстояние, а не вероятность правильного ответа.
4. Измените 7000 на 9000 в `data/scholarships.md`, повторите индексацию и поиск. Старая версия чанка удаляется.
5. Переместите один файл за пределы `data/`, повторите индексацию: его чанки удалятся. Верните файл для следующей группы.
6. Перейдите к реальному провайдеру, убрав `--demo`, и сравните запросы со словами из документа и с синонимами.
7. `chapter2 multivector "Стипендия" --demo` — проследите связь короткого представления с полным исходным документом. В demo представление — первые 220 символов; реальная суммаризация выполняется только без `--demo`.

Подробный сценарий занятия и упражнения: [docs/lesson.md](docs/lesson.md).

## Состав проекта и связь с книгой

| Раздел главы / примеры ch2/py | Где смотреть |
|---|---|
| Загрузчики TXT, web, PDF (a–c), с. 55–58 | `pipeline.load_documents`, пример веб-загрузки в notebook |
| Рекурсивный splitter, код, Markdown (d–f), с. 58–62 | `split_documents`, `split_markdown`, notebook |
| Эмбеддинги (g–h), с. 62–65 | `make_embeddings`, notebook |
| Векторное хранилище / PGVector (i), с. 65–69 | Постоянный Chroma в `open_store`; пояснение замены ниже |
| Record manager (j), с. 69–74 | `SQLRecordManager` + `index` в `synchronize` |
| MultiVectorRetriever (k), с. 74–79 | `advanced.py`: представления → `doc_id` → полные документы |
| RAPTOR / ColBERT (l), с. 79–82 | Обсуждение и задания в `docs/lesson.md` |

Код создан для этого практикума с опорой на структуру [официальных примеров главы](https://github.com/langchain-ai/learning-langchain/tree/master/ch2/py). Используется современное разделение пакетов: `langchain_core`, `langchain_classic`, `langchain_text_splitters` и интеграции. Импорты старого `langchain.indexes` из книги перенесены в `langchain_classic.indexes`.

Для запуска без Docker и PostgreSQL используется локальный **Chroma**, а записи об индексации хранятся в **SQLite**. Это замена инфраструктуры, сохраняющая этапы учебного процесса; конфигурация PGVector в проект не входит. RAPTOR и ColBERT обсуждаются как расширение, не реализованы и не нужны для запуска.

## Хранение и обновления

- `.index/demo/` и `.index/live/` изолированы: демонстрационные и настоящие векторы не смешиваются.
- В каждой папке: `chroma/` — тексты, метаданные и векторы; `records.sqlite` — записи LangChain; `config.json` — модель, URL и параметры splitter без ключа.
- `index` читает **весь каталог** и вызывает `cleanup="full"`. Поэтому удаляются и старые версии, и исчезнувшие файлы. В книге показан `incremental`: он очищает только источники, присутствующие в текущем вызове. Нельзя передавать частичный набор документов в full-индексацию.
- Пустой каталог защищён от случайной очистки. Намеренно удалить все записи: `chapter2 index --demo --allow-empty` (или без `--demo` для live).
- При смене embedding-модели, URL, размера чанка или overlap используйте новую папку: `chapter2 index --index-dir .index-experiment`. При поиске укажите ту же папку. Изменение размерности модели с тем же ID также требует нового индекса.
- Не запускайте несколько процессов индексации одновременно. Chroma и SQLRecordManager не образуют единую транзакцию. После аварии между их записями надёжный учебный способ восстановления — новый `--index-dir` и полная индексация.
- Для новых материалов положите `.txt`, `.md`, `.pdf` в `data/`. PDF обрабатывается постранично; сканы без текстового слоя требуют OCR, которого здесь нет. Ошибка чтения файла останавливает индексацию до её обновления.

## Проверка

```bash
python -m pytest -q
```

Тесты без внешнего API проверяют повторную индексацию без новых эмбеддингов, изменение и удаление файлов, сохранение индекса, разделение конфигураций, MultiVectorRetriever и тело запроса к `/embeddings`.

`requirements-lock.txt` фиксирует проверенное окружение Python 3.12/Linux; на других ОС pip может подбирать платформенные колёса. Для ноутбука Jupyter устанавливается отдельным extra. Файл `VERIFICATION.md` содержит результаты проверки этой сборки.
